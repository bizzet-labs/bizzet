# 実装の状況

## このページの目的と範囲

このページは、ETHGlobal Tokyo 2026 の期間中（2026年9月25日〜27日）に、ベータ版の機能のうち何を作り、何をまだ作っていないかを、機能 ID と画面 ID ごとに示します。扱うのは各機能と画面の実装の状態と、それをどう確かめたかだけで、機能や画面の中身、設計の考え方はこのページでは扱いません。状態は「実装済み」「一部」「未実装」の3つで表し、「一部」のものは足りない部分を表の下に書きます。

## まとめ

ダッシュボードの機能と、ウォレットの土台になるオンチェーンの部品（Safe、パスキーの署名者、Roles v2 の設定、ENSv2 の名前とレコード）はでき上がっており、Sepolia のフォークで動きを確かめました。本部と店舗の Safe の出金は、ウォレットでのパスキーの署名から実行まで通るようになり、客は値札の QR から ENS の名前で受取先を解決し、JPYC か USDC で、受取通貨と違えば Uniswap v4 で交換して支払えます。一方で、レシートと Checkout コントラクトはまだ作っていません。自動テストは、vitest（ダッシュボード 11件、ウォレット 65件）とコントラクトのフォークテスト 23件がすべて通り、型チェックも通っています。

## 値札と決済

| ID | 機能 | 状態 | 確かめた方法 |
| --- | --- | --- | --- |
| P-01 | JPYC と USDC での価格の表示 | 一部 | vitest での換算の確認と、決済ページの表示の確認 |
| P-02 | QR か NFC での支払いの受け付け | 一部 | 値札の QR の作成と、決済ページの表示の確認 |
| P-03 | 決済時の交換 | 一部 | フォークテストでの、Uniswap v4 での交換と店舗への直接の受け取り |
| P-04 | 「処理中」と「済」の表示 | 実装済み | 決済ページの型チェックとビルド |
| P-05 | 商品と価格の登録 | 未実装 | — |
| P-06 | 受取先と受取通貨の設定 | 実装済み | フォークテストでの、店舗の名前のレコードの Universal Resolver での解決 |
| P-07 | レシートの識別子の登録 | 未実装 | — |
| P-08 | 買った記録による割引 | 未実装 | — |

決済ページは、値札の QR が指す店舗の ENS の名前を Universal Resolver で解決し、客のブラウザのウォレットから受取先へ ERC-20 を送ります。P-01 は USDC の価格をデモ用の固定レートで換算しており、P-02 は QR だけで NFC には対応していません。P-04 は、客のウォレットからの実際の送金ではまだ試していません。P-06 は、店舗の追加とグループの設定から ENS に書き込みますが、実際の Sepolia での本部の名前の登録はまだ行っていません。P-03 は、Checkout コントラクトの代わりに、客のウォレットから Uniswap v4 の Universal Router を直接呼び、交換した通貨を店舗の Safe に届ける形で作りました。Sepolia の JPYC/USDC のプールには流動性がないため、流動性を足すまで実際の Sepolia では交換を選べません。P-05、P-07、P-08 は、Checkout コントラクトと Semaphore との連携を作っていないため未実装です。

## オンチェーンの部品

| 部品 | 状態 | 確かめた方法 |
| --- | --- | --- |
| Safe の設定と CREATE2 でのアドレスの計算 | 実装済み | フォークテストでの、デプロイ済みの Safe とのアドレスの一致 |
| パスキーの署名者と ERC-4337 の UserOperation | 実装済み | フォークテストでの `handleOps` の通しの実行と、Sepolia での実際の送信 |
| SafeTx のハッシュの計算 | 実装済み | フォークでの、Safe の `getTransactionHash` との一致 |
| Roles v2 の設定 | 実装済み | フォークテストでの、キーパーが本部の Safe への送金しかできないことの確認 |
| ENSv2 の組み込み（本部の名前、店舗のサブネーム、受取先のレコード） | 実装済み | フォークテストでの、登録・レコードの書き込み・解決の確認 |
| 店舗の Safe の入れ子の承認（本部の Safe のコントラクト署名） | 実装済み | フォークテストでの、本部のオーナー2人の署名による店舗の execTransaction の成功と、1人の署名での失敗 |
| 署名がそろった取引の送信 | 一部 | フォークテストでの、1つの UserOperation での署名者の配置と execTransaction |
| Uniswap v4 での交換（見積もり、Permit2、Universal Router、全範囲の流動性の追加） | 実装済み | フォークテストでの、JPYC と USDC の両方向の交換と見積もりの一致 |
| Checkout コントラクト | 未実装 | — |
| Semaphore v4 との連携 | 未実装 | — |

パスキーの署名者と ERC-4337 については、Pimlico を通した実際の Sepolia での UserOperation で、ガス代を肩代わりしてもらいながら Safe と署名者をデプロイできたことを確かめました。その取引のハッシュは 0xe1bfcc2134d73fb42c8c8b7e26c7581baeec14ad02d4f0764e610008ab5ca6c4 で、Sepolia の Etherscan（https://sepolia.etherscan.io/tx/0xe1bfcc2134d73fb42c8c8b7e26c7581baeec14ad02d4f0764e610008ab5ca6c4 ）で確かめられます。
