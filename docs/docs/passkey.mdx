# パスキー

## 何を解くか

メンバーが秘密鍵やシードフレーズを自分で管理すると、紛失や漏えいのおそれがあり、店舗のスタッフには扱いも難しくなります。パスキーを使うと、メンバーは端末の生体認証だけでウォレットの画面にログインして署名でき、鍵を意識せずに済みます。

## できること

| 用途 | 内容 | 使うメンバー |
| --- | --- | --- |
| ログイン | ウォレットの画面へのログイン | すべてのメンバー |
| 署名 | Safe のオーナーとしての、出金の承認への署名 | Owner、Approver |

## 仕組み

メンバーごとにパスキーの署名者コントラクトを作り、Owner と Approver の署名者を、所属するグループの Safe のオーナーに加えます。本部の2人承認は、経営と会計部それぞれのパスキーで満たせます。Viewer は Safe のオーナーにならないため、パスキーはログインにだけ使います。

## 設計の選択

- **ガス代はメンバーに持たせない。** パスキーはガス代のトークンを持てないため、署名したあとの取引は Safe4337Module を通して送り、ガス代は ERC-4337 の Paymaster が払います。
- **署名の検証が安いチェーンを優先する。** パスキーの署名方式（P-256）は、チェーンに専用の検証機能があるとガス代が安くなります。ベータ版のホームである Ethereum Sepolia と、本番の候補のうち Ethereum と Polygon は対応済みです。仮置き：Avalanche の対応は、確認できた時点で更新します。
- **パスキーはウォレットの画面にだけ使う。** パスキーはブラウザやOSが登録したドメインに紐づけて保存するため、ウォレットとダッシュボードがドメインの異なる別のアプリだと、一方で登録したパスキーを他方で使えず、iPhone の Safari では他端末のパスキーを読み取る QR コードが表示されてしまいます。このためダッシュボードのログインはメールアドレスとパスワードで行い、パスキーの登録と利用はウォレットの画面にだけ置きます。
- **紛失に備えて入れ替えの手順を持つ。** 端末間で同期されたパスキーは端末を替えても使えます。失った場合は、Safe のほかのオーナーの承認で、失ったパスキーの署名者を外し、新しいものを加えます。
