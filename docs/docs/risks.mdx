# リスク

| リスク | 重さ | 対処 |
| --- | --- | --- |
| 「店舗向け」に聞こえ、EC 事業者に無関係と誤解される | 中 | 呼称を「ビジネス向けウォレット」に統一し、値札は一例と明記 |
| スコープが横に広がり、値札もウォレットも半端に終わる | 高 | 機能は1つずつ、役割は3つ、拠点は2つから |
| 「通貨を切り替えて表示する値札」に見え、技術的に新しくないと受け取られる | 中 | 価値はレジをなくすことと、客と店が別の通貨で同じ商品を見ていることにある。切替表示は演出として残し、中身は決済まで作る |
| JPYC/USDC の Uniswap プールが薄く、交換が失敗する | 高 | bizzet 自身がプールに流動性を提供して厚くする |
| 自動ブリッジの到着が遅れる・止まる（本番） | 中 | 「ブリッジ待ち」の売上を、ダッシュボードで残高と分けて見せる |
| Roles や Sweep の権限設定に穴がある | 中 | 拒否されるべき操作を先にテストに書く |
| 中継用アカウントの鍵が漏れる | 中 | オーナーの署名がない取引は Safe が拒むため、グループの資金には届かない。漏れた場合は鍵を替え、Paymaster の対象を新しいアカウントに移す |
| 本部の Owner か Approver がパスキーを失う | 中 | 本部の Safe のオーナーを3人以上にし、残る2人で承認を続ける |
| ブロックを待つ間に「決済が遅い」印象になる | 中 | 支払いを受け付けた時点で「処理中」を出し、ブロックが出たら「済」に部分書き換えする |
| 店の回線が不安定で値札が `Paid` を拾えない | 中 | 購読が切れたら最終ブロックから再取得 |
| 「ステーブルコインで受け取って法的に大丈夫か」と聞かれる | 低 | JPYC の資金移動業型という事実だけ述べ、法的助言に踏み込まない |

交換の失敗時は revert して値札が「済」にならないため、客の資金は動きません。ブリッジの到着待ちも資金の消失ではなく、画面でそう分かるようにします。権限のテストで先に書くのは、店舗のスタッフによる出金の実行・運用者以外による価格の変更・キーパーの宛先の変更の3つです。
