# パスキー

## 何を解くか

メンバーが秘密鍵やシードフレーズを自分で管理すると、紛失や漏えいのおそれがあり、店舗のスタッフには扱いも難しくなります。パスキーを使うと、メンバーは端末の生体認証だけでウォレットの画面にログインして署名でき、鍵を意識せずに済みます。

## できること

| 用途 | 内容 | 使うメンバー |
| --- | --- | --- |
| ログイン | ウォレットの画面へのログイン | すべてのメンバー |
| 署名 | Safe のオーナーとしての、提案（出金・オーナーの変更・Safe の設定）への署名 | Owner、Approver |

## 仕組み

メンバーごとにパスキーの署名者コントラクトを作り、本部の Owner と Approver の署名者を本部の Safe のオーナーに加えます。パスキーの登録は、招待リンクか追加用リンクを開いた画面でだけ行い、サーバーがチャレンジと公開鍵を確かめてから保存します。本部の2人承認は、経営と会計部それぞれのパスキーで満たせます。Viewer は Safe のオーナーにならないため、パスキーはログインにだけ使います。

## 設計の選択

- **ガス代はメンバーに持たせない。** メンバーは Safe の取引のハッシュにパスキーで署名するだけで、署名がそろった取引は bizzet の中継用アカウントが ERC-4337 で送り、ガス代は Paymaster が払います。署名にガス代や期限が含まれないため、2人目の署名まで何日空いても送れます。
- **署名の検証が安いチェーンを優先する。** パスキーの署名方式（P-256）は、チェーンに専用の検証機能があるとガス代が安くなります。パスキーの署名を検証するのはホームチェーンだけで、ベータ版のホームの Ethereum Sepolia と、本番のホームの Polygon PoS はどちらも対応済みです。
- **パスキーはウォレットの画面にだけ使う。** パスキーはブラウザやOSが登録したドメインに紐づけて保存するため、ウォレットとダッシュボードがドメインの異なる別のアプリだと、一方で登録したパスキーを他方で使えず、iPhone の Safari では他端末のパスキーを読み取る QR コードが表示されてしまいます。このためダッシュボードのログインはメールアドレスとパスワードで行い、パスキーの登録と利用はウォレットの画面にだけ置きます。
- **紛失は3人以上のオーナーで吸収する。** 端末間で同期されたパスキーは端末を替えても使えます。本部の Safe のオーナーは3人以上にするため、1人がパスキーを失っても残る2人で出金を承認できます。失ったパスキーを入れ替える手順は、ベータ版では作りません。
