# 自動ブリッジ

## 何を解くか

同一チェーンの変換は決済時に1トランザクションで終わります（[プライシングの決済の流れ](./pricing.mdx#仕組み--決済の流れ)）。「着金後に自動で変換して一元管理」が意味を持つのは、客が別のチェーンで払った分に限られます。チェーンをまたぐ交換は1トランザクションで閉じられないためブリッジ到着後にまとめて替え、1件数百円の売上を都度ブリッジするとガス代で消えるのでバッチを前提にします。起動するキーパーの権限は「宛先＝ホームの Safe」に固定し、他へは1円も送れないようにします。

## 仕組み

<BridgeDiagram />

Base・Arbitrum・OP Mainnet など、CCTP v2 に対応したチェーンで USDC として着金した売上を、Safe 上の Sweep モジュールが閾値か1日1回で起動して集め、CCTP でホームチェーンへ移し、受け取る通貨が JPYC なら Uniswap で JPYC に替え、ホームの法人ウォレットに1つの台帳として集約します。Sweep の宛先はホームの Safe に固定されています。同一チェーン（ホームの Polygon での着金）は決済時に交換済みなので、Sweep を通らず直接ホームに入ります。

「着金したら自動で」を人の署名なしで、かつ資金を盗めない形で実現する要点は Sweep の権限の狭さです。キーパー（Gelato や Chainlink Automation 等）が呼べるのは「ホームの Safe へ送る」だけです。USDC の移動は Circle の CCTP（ネイティブの焼却・発行）で、ラップ資産を持ちません。使うのは CCTP v2 だけで、CCTP v1 は 2026年10月31日から縮小が始まり 12月1日に停止するため使いません。

## 設計の選択

| 設計の選択 | 採る | 採らない |
| --- | --- | --- |
| 変換のタイミング | 同一チェーンは決済時に即時、他チェーンは閾値バッチ | 全件を着金ごとに変換（ガス代で売上が消える） |
| ブリッジ | CCTP v2（高速転送に対応するチェーンは高速、ほかは標準） | CCTP v1（2026年12月に停止）、汎用ブリッジのラップ資産、自前のリレー |
| 起動者 | 宛先固定の Sweep モジュール＋外部キーパー | 店主の手動署名、鍵を持つ自前サーバー |
| 台帳 | `Paid` と Sweep の到着を1つの仕訳に（着金時レートで円換算） | チェーンごとの残高を並べるだけのダッシュボード |
| JPYC の扱い | ホームチェーンでだけ持つ | JPYC 自体のブリッジ（公式の経路がない） |
| JPYC での支払い | ホームチェーンでだけ受け付ける | ほかのチェーンの JPYC を受け付ける（ホームへ移せない） |

円換算で生じる差額は、仕訳上は為替差損益の行に落とします。

## ホームチェーン

ホームチェーンは、次の3つを満たすチェーンから選びます。

| 条件 | 理由 |
| --- | --- |
| JPYC が発行されている | JPYC はホームチェーンでだけ持つため |
| ほかのチェーンの USDC を CCTP で受け取れる | 自動ブリッジの到着先になるため |
| Uniswap v4 がある | 決済時の交換と、表示レートの出所になるプールを置くため |

### ベータ版

ベータ版のホームチェーンは Ethereum Sepolia で、JPYC の公式テストトークン、CCTP v2、Uniswap v4 がすべて配置済みです。ベータ版は客の支払いも Sepolia だけで受け付けるため、自動ブリッジは動かしません。店舗から本部への売上の集約は、同じ Sepolia の中で Sweep が行います。

### 本番

本番のホームチェーンは Polygon PoS とします。JPYC は Ethereum・Polygon・Avalanche・Kaia で発行されていますが、Kaia には Uniswap v4 がありません。残る3つのうち、Polygon はパスキーの署名の検証に専用の機能があり、ガス代も Ethereum より安いため、メンバーの署名と決済時の交換を毎日くり返すホームに向きます。

| チェーン | CCTP v2 | 転送方式 | 自動ブリッジでの扱い |
| --- | --- | --- | --- |
| Ethereum | 対応 | 高速・標準 | 客が払うチェーン |
| Polygon PoS | 対応 | 標準のみ | ホーム |
| Avalanche | 対応 | 標準のみ | 客が払うチェーン |
| Base、Arbitrum、OP Mainnet | 対応 | 高速・標準 | 客が払うチェーン |
| Sui | 未対応（v1 のみ） | — | 今後の対応予定 |
| Kaia | 未対応 | — | 今後の対応予定 |

標準転送は送り元チェーンの確定を待つため、Avalanche から移す売上は、高速転送のチェーンより本部のウォレットへの到着が遅くなります。ホームの Polygon で払われた売上は、決済時に交換済みのためブリッジを通りません。

### 今後の対応予定

| チェーン | 対応の条件 | 状況 |
| --- | --- | --- |
| Sui | CCTP v2 の Sui 対応と、Sui での受け取りの別実装 | Circle は 2026年10月31日までに v2 に対応させるとしている |
| Kaia | CCTP の Kaia 対応 | Circle の対応予定の発表はない |

Sui は EVM ではないため、Safe・Roles v2・Sweep はそのままでは動かず、CCTP v2 が対応しても、Sui で売上を受け取る仕組みを別に作る必要があります。Kaia は汎用ブリッジのラップ資産を使わない方針のため、CCTP が対応するまでは客が払うチェーンに加えません。
