# ENS の設計

ENSv2 を bizzet に組み込むための設計を、実装できる粒度でまとめます。対象は、本部の名前の登録、店舗のサブネームの登録、受取先のレコードの書き込み、画面での名前の解決です。値札や Checkout コントラクトからの解決、メンバーのサブネームは、ベータ版で作らないため扱いません。

## 全体の構成

本部の名前（例：`bizzet.eth`）を ENSv2 の ETHRegistrar で登録し、その下に本部専用のサブネームのレジストリを1つ置いて、店舗の名前（例：`shibuya.bizzet.eth`）を登録します。本部と店舗の名前は同じ1つのリゾルバを使い、各名前にグループの Safe のアドレスと受取通貨を書きます。名前の登録とレコードの書き込みは bizzet の運用者の鍵が行い、ダッシュボードでは本部の Owner だけがその指示を出せます。ダッシュボードとウォレットは Universal Resolver で名前を解決し、ENS に書かれた値を画面に出します。

## 使うコントラクト

いずれも ENS が Sepolia に配置したもので、bizzet は Solidity を書きません。アドレスは ENS の公式ドキュメントの配置一覧によるもので、どれも Sepolia 上にコードがあることを確かめています（2026年9月27日確認）。

| コントラクト | アドレス | 使い方 |
| --- | --- | --- |
| ETHRegistrar | `0xabe76f6c8dfced81aa5a2bb8034202a7136b94ca` | 本部の名前の登録（commit と register） |
| ETHRegistry | `0x657ea849311d3d5823348dded7c2aaafb3ede09e` | `.eth` の名前の記録（登録で自動的に書かれる） |
| VerifiableFactory | `0x9e726eb570beb6bceb495ab8cda7df517d4e841c` | サブネームのレジストリとリゾルバのプロキシの配置 |
| UserRegistryImpl | `0xa80338aaa8d23831cea25e858d1774534abb0263` | サブネームのレジストリの実装 |
| PermissionedResolverImpl | `0x14f09fd05d4585759e54844dc9b00147131cf243` | リゾルバの実装 |
| UniversalResolverV2 | `0x5d25c1d6acbb71b7a28aa7899618a3412a8303e3` | 名前の解決 |
| StandardRentPriceOracle | `0x9b0b9c65bdaf9794ff7697e4dcfb1f50581072bb` | 登録料金の算出 |
| MockUSDC | `0x16f95d91dba7da3aca778ec053df0ff6c6a8aa8e` | 登録料金の支払い（小数6桁） |

## 名前の構成

| 名前 | 例 | 置く場所 | 持ち主 |
| --- | --- | --- | --- |
| 本部 | `bizzet.eth` | ETHRegistry | 運用者の鍵 |
| 店舗 | `shibuya.bizzet.eth` | 本部のサブネームのレジストリ | 運用者の鍵 |

店舗ごとの独自のレジストリは置かず、店舗の名前はすべて本部のサブネームのレジストリに直接登録します。店舗の名前の有効期限は、本部の名前の有効期限と同じにします。

### ラベルの決め

- 本部のラベルは初期セットアップで1回だけ決め、店舗のラベルは店舗を作るときに本部の Owner が入れる
- ラベルは英小文字・数字・ハイフンの3〜32文字とし、ENSIP-15 の正規化（viem の `normalize`）を通した値を使う
- 同じ本部の中でラベルは重複させない

## レコード

本部と店舗のどちらの名前にも、次のレコードを書きます。

| レコード | キー | 値 |
| --- | --- | --- |
| アドレス | `addr`（コインタイプ 60） | グループの Safe のアドレス |
| 受取通貨 | テキスト `bizzet.currency` | `JPYC` か `USDC` |
| 表示名 | テキスト `description` | グループの名前 |

グループの Safe が未設定のうちは、アドレスのレコードを書かず、Safe の設定を確定した時点で書きます。受取通貨の既定値は `JPYC` とし、本部の Owner がグループの設定画面で変えるとテキストレコードを書き換えます。レコードの書き込みは、リゾルバの `multicall` で1回の取引にまとめます。

## 権限

| 対象 | 与えるロール | 相手 |
| --- | --- | --- |
| サブネームのレジストリ | 登録・リゾルバの設定・更新と、それぞれの管理者のロール | 運用者の鍵 |
| リゾルバ | アドレスとテキストの書き込みと、それぞれの管理者のロール | 運用者の鍵 |

ロールの値は ENSv2 のコントラクトの定義に従います。サブネームのレジストリでは、登録が `1 << 0`、更新が `1 << 16`、リゾルバの設定が `1 << 24` です。リゾルバでは、アドレスの書き込みが `1 << 0`、テキストの書き込みが `1 << 4` です。管理者のロールは、それぞれの値を128ビット左にずらした値です。どのロールもリソース単位で与える仕組みのため、ロールを持たない鍵はレコードを書き換えられません。

## 流れ

### 初期セットアップ（1回だけ）

初期セットアップは、`packages/contracts` のスクリプトを運用者が1回実行して行います。

1. VerifiableFactory の `deployProxy` で、サブネームのレジストリ（UserRegistryImpl）のプロキシを配置し、`initialize` で運用者の鍵にレジストリのロールを与える
2. 同じく、リゾルバ（PermissionedResolverImpl）のプロキシを配置し、`initialize` で運用者の鍵にリゾルバのロールを与える
3. MockUSDC を `mint` で発行し、ETHRegistrar に登録料金ぶんを `approve` する
4. ETHRegistrar の `makeCommitment` と `commit` で登録を予約し、60秒以上待つ。予約は1日で失効する
5. ETHRegistrar の `register` で、持ち主を運用者の鍵、サブネームのレジストリを手順1のプロキシ、リゾルバを手順2のプロキシ、期間を1年、支払いのトークンを MockUSDC として登録する
6. 本部の名前のレコードを書き、手順1と2のアドレスと本部の名前をデータベースに保存する

登録料金は、ETHRegistrar の `getRegisterPrice` で登録の直前に読みます。6文字のラベルを1年登録すると 8.000021 MockUSDC でした（2026年9月27日確認）。

### 店舗の追加

1. 本部の Owner が、ダッシュボードの店舗の追加で、店舗の名前とラベルを入れる
2. ダッシュボードのサーバーが、グループとその Safe の設定を保存したあと、サブネームのレジストリの `register` で店舗の名前を登録する
3. 続けて、リゾルバの `multicall` で店舗の名前のレコードを書く
4. どちらかの取引が失敗しても、グループの作成は取り消さない。名前の状態を「失敗」として残し、グループの設定画面からやり直せるようにする

### 名前の解決と表示

- ダッシュボードのグループ一覧とグループ詳細、ウォレットのホームに、グループの名前を出す
- 表示するアドレスと受取通貨は、データベースの値ではなく Universal Resolver で解決した値を使う
- 解決したアドレスがデータベースの Safe のアドレスと違う場合は、警告を出す

## データの持ち方

| 表 | 持つもの |
| --- | --- |
| ENS の設定 | 本部の名前、サブネームのレジストリとリゾルバのアドレス、有効期限（組織に1行） |
| グループ | 名前のラベル、受取通貨、名前の状態（未登録・登録済み・失敗）、登録した取引のハッシュ |

## 鍵と設定の置き場所

| 設定 | 置き場所 | 用途 |
| --- | --- | --- |
| `ENS_OPERATOR_PRIVATE_KEY` | ダッシュボードのサーバーの環境変数と、初期セットアップのスクリプトの環境変数 | 名前の登録とレコードの書き込み |
| `SEPOLIA_RPC_URL` | 同上 | 取引の送信と名前の解決 |

運用者の鍵は資金を持たないグループの Safe とは別の鍵で、Sepolia ETH のガス代だけを持ちます。漏れても書き換えられるのは ENS のレコードだけで、グループの資金には届きません。ただし受取先のアドレスを書き換えられるため、漏れた場合は鍵を替えてリゾルバのロールを移し、画面の警告（解決したアドレスと Safe の違い）で書き換えに気づけるようにします。

## 設計の選択

| 設計の選択 | 採る | 採らない |
| --- | --- | --- |
| 名前の持ち主 | 運用者の鍵 | 本部の Safe（書き換えのたびに2人承認と Safe の配置が要る） |
| 店舗の名前の置き場所 | 本部のサブネームのレジストリ | 店舗ごとの独自のレジストリ（配置の手間が店舗の数だけ増える） |
| リゾルバ | 本部と店舗で共有する PermissionedResolver | 名前ごとのリゾルバ（ロールの付与を名前ごとにくり返す） |
| 受取先の表し方 | `addr` のレコード | 独自のテキストレコード（一般のウォレットが読めない） |
| 画面での値 | Universal Resolver で解決した値 | データベースの値（ENS に書いたことを確かめられない） |
| 送金の方法 | 運用者の鍵からの通常の取引 | 中継用アカウントと Paymaster（ENS の書き込みは資金の操作でなく、2人承認が要らない） |
