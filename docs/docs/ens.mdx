# ENS

## 何を解くか

店舗の受取先や組織の階層をチェーン上の名前で表すことで、値札や購入ボタンといった決済チャネルに設定を埋め込まず、差し替えを1箇所で済ませます。名前の仕組みには ENS を使い、契約バージョンは ENSv2 を前提にします。このページは ENS を使う機能と、ENSv2 を選ぶ根拠を扱い、Safe・権限管理・自動ブリッジの仕組みそのものは扱いません。

## ENS を使う機能

ENS を使うのは、受取先の設定と組織図の2つに限ります。送金・承認・権限の付与は Safe と権限管理の側で完結し、ENS には置きません。

| 機能 | ENS に置くもの | 読む側 |
| --- | --- | --- |
| 受取先の設定 | 店舗の名前のテキストレコード（受取通貨、受取ウォレットのアドレス） | 値札、購入ボタン、Checkout コントラクト |
| 組織図 | 本部・店舗・メンバーを表すサブネーム | ダッシュボード、ウォレットの画面 |

### 受取先の設定

店舗ごとの名前（例：`a.shop.eth`）のテキストレコードに、受け取る通貨（JPYC か USDC）と受取ウォレットのアドレスを書きます。値札・購入ボタン・Checkout コントラクトは決済のたびにこのレコードを解決して送金先を決めるため、受取先を変えるときはレコードを1回書き換えるだけで、全チャネルに反映されます。

レコードを書く役割は、ENSv2 のレコード単位の権限で Owner のロールに限定します。Approver と Viewer は読むだけで書けません。

### 組織図

本部の名前（例：`shop.eth`）の下に店舗のサブネーム（`a.shop.eth`）、その下にメンバーのサブネーム（`taro.a.shop.eth`）を置き、名前を辿るだけで所属が分かるようにします。ユーザー管理の「グループ ＝ Safe」と対にして、店舗の名前は店舗の Safe を、メンバーの名前はメンバーのウォレットを指します。役職や所属の履歴はオンチェーンにせず、画面側に置きます。

## ENSv2 の強み

ENSv2 は、名前ごとに独自のレジストリとリゾルバを持てる階層構造に作り直された ENS の新バージョンです。2026年2月20日に ENS Labs が公開したアーキテクチャ解説を根拠に、このプロジェクトに効く点を挙げます。

| 強み | 内容 | このプロジェクトでの効果 |
| --- | --- | --- |
| 階層レジストリ | 名前ごとに独自のレジストリを持ち、サブツリーを1回の操作で差し替え可能 | 閉店や退職時にメンバーの名前を一括でリセット |
| レジストリの共有 | 複数の名前が同じレジストリを指せる | ロール構成を1箇所で定義して全店舗に適用 |
| レコード単位の権限 | リゾルバ・名前・レコードの3階層で書き込み権限を分割 | 受取先レコードの書き手を Owner に限定 |
| 期限切れの即時反映 | 期限切れの名前とサブネームが即座に消える | 消えた店舗の名前が決済先として残らない |
| エイリアス | 複数の名前で1つのリゾルバを共有し、1回の更新で全名に反映 | 屋号を複数持つ店舗の設定を1箇所で管理 |
| Universal Resolver | クライアントは1つのコントラクトを呼ぶだけで解決が完結 | viem の最新版なら追加の解決コードが不要 |
| 互換性 | 既存の ENSv1 の名前はフォールバックで解決され続け、任意のタイミングで移行可能 | v1 の名前を持つ店舗もそのまま参加可能 |
| L1 専用 | 独自 L2（Namechain）の開発中止により、Ethereum 本体の保証をそのまま享受 | L2 のシーケンサや更新権限のリスクを持ち込まない |

## 設計の選択

| 設計の選択 | 採る | 採らない |
| --- | --- | --- |
| 名前の仕組み | ENSv2（階層レジストリとレコード単位の権限） | ENSv1（NameWrapper の fuse で権限を表す） |
| 受取先の置き場所 | 店舗の名前のテキストレコード | チャネルごとに埋め込む（差し替えのたびに全チャネルを直す） |
| 組織の表現 | サブネームの階層 | 画面側のデータベースだけ（チェーン上の Safe と対応が取れない） |
| 名前の解決 | Universal Resolver 経由 | リゾルバのアドレスを直接固定する（ENSv2 移行で壊れる） |
| 受取先レコードの書き手 | Owner のロールだけ | 名前のオーナー全員（Approver も書けてしまう） |

## ベータ版

ベータ版のホームチェーンである Ethereum Sepolia には、2026年2月時点で ENSv2 のベータ版がデプロイされています。Universal Resolver は mainnet と Sepolia で同じアドレスのため、チェーンを Sepolia に向けるだけで ENSv2 を試せます。Sepolia での名前の登録には、Sepolia ETH と、誰でも発行できるテスト用の USDC を使います。

ENSv2 の mainnet への展開時期は 2026年2月時点で公表されていないため、ベータ版の実装は Universal Resolver 経由の解決にとどめ、ENSv1 の名前でも同じコードで動くようにします。

## 決まっていないこと

- **店舗ごとの独自レジストリ**：仮置き。店舗の名前に独自のレジストリを持たせるか、本部のレジストリに店舗を直接登録するかを、レジストリのデプロイと接続にかかるコントラクト側の作業量を見積もった時点で更新します。
- **本部の名前の取得**：仮置き。`shop.eth` のような本部の名前を、bizzet が取得して店舗に貸すか、事業者が自分で取得するかを決めた時点で更新します。
