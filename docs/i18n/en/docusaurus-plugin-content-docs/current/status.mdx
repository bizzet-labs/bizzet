# Implementation status

## Purpose and scope of this page

This page shows, for each feature ID and screen ID, what was built and what has not yet been built for the beta during ETHGlobal Tokyo 2026 (September 25-27, 2026). It covers only the implementation status of each feature and screen and how that status was verified; it does not cover the content of the features and screens or the reasoning behind their design. Status is expressed as one of three values, "Done," "Partial," or "Not implemented," and for "Partial" items, what is missing is written below the table.

## Summary

The dashboard's features and the on-chain building blocks underpinning the wallet (Safe, the passkey signer, the Roles v2 configuration, and ENSv2 names and records) are complete, and their behavior was verified on a Sepolia fork. Withdrawals from the headquarters and store Safes now work end to end, from the passkey signature in the wallet through to execution, and customers can resolve the recipient from the price tag's QR code via an ENS name and pay in JPYC or USDC, swapping through Uniswap v4 when the currency differs from what the recipient accepts. Receipts and the Checkout contract, however, have not yet been built. Automated tests all pass, covering vitest (11 for the dashboard, 65 for the wallet) and 23 contract fork tests, and type checking also passes.

## Wallet

| ID | Feature | Status | Verification method |
| --- | --- | --- | --- |
| W-01 | Passkey registration and login | Done | Login signature verification in vitest, and session confirmation on the development server |
| W-02 | Balance check | Done | API confirmation with a disposable database and the development server |
| W-03 | Transfer and refund requests | Partial | Amount, recipient, and nonce checks in vitest, and API confirmation on the development server |
| W-04 | Signing withdrawal approvals | Done | API confirmation with a disposable database, and a fork test verifying signatures |
| W-05 | Executing a withdrawal with two approvals | Partial | Successful execTransaction on the headquarters and store Safes in a fork test |
| W-06 | Moving and swapping revenue from other chains | Not implemented | — |
| W-07 | Issuing a link to add a password | Done | Link assembly in vitest, and API confirmation on the development server |

For W-01, the server verifies the passkey signature over a single-use challenge against the stored public key, and issues a signed session cookie. Login with an actual passkey has not yet been tried. For W-03, a store member's refund request is made in the wallet's WS-04, and the withdrawal is created in the dashboard's DS-09; requests from actual members have not yet been tried. For W-04's store Safe proposal, the headquarters Owner and Approver sign a SafeMessage on the headquarters Safe, which is then passed to the store Safe as a contract signature from the headquarters Safe. W-05 currently runs on a provisional path that, instead of a relayer account, sends through Pimlico from the passkey account of whoever signed last; an actual send on Sepolia has not yet been tried. Group Safes are configured in the dashboard, and withdrawals are not executed for an unconfigured Safe. W-06 has not been built, since the beta has no automatic bridge.

## Price tags and payment

| ID | Feature | Status | Verification method |
| --- | --- | --- | --- |
| P-01 | Price display in JPYC and USDC | Partial | Conversion confirmation in vitest, and display confirmation on the payment page |
| P-02 | Accepting payment via QR or NFC | Partial | Generating a price tag QR code, and display confirmation on the payment page |
| P-03 | Swap at payment time | Partial | A Uniswap v4 swap and direct receipt by the store in a fork test |
| P-04 | "Processing" and "Done" display | Done | Type checking and build of the payment page |
| P-05 | Registering products and prices | Not implemented | — |
| P-06 | Configuring recipient and recipient currency | Done | Resolution of a store's name record via the Universal Resolver in a fork test |
| P-07 | Registering a receipt identifier | Not implemented | — |
| P-08 | Discounts based on purchase history | Not implemented | — |

The payment page resolves the store's ENS name pointed to by the price tag's QR code via the Universal Resolver, and sends ERC-20 tokens from the customer's browser wallet to the recipient. P-01 converts the USDC price using a fixed demo rate, and P-02 supports only QR, not NFC. P-04 has not yet been tried with an actual transfer from a customer's wallet. P-06 writes to ENS from store creation and group configuration, but registering the headquarters name on actual Sepolia has not yet been done. P-03 was built so that, instead of a Checkout contract, the customer's wallet calls Uniswap v4's Universal Router directly and delivers the swapped currency to the store's Safe. Because the Sepolia JPYC/USDC pool has no liquidity, the swap option cannot be chosen on actual Sepolia until liquidity is added. P-05, P-07, and P-08 are not implemented because integration with the Checkout contract and Semaphore has not been built.
