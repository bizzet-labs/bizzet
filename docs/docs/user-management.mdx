# ユーザー管理

## 何を解くか

1拠点なら経営と会計部の2人で済みますが、本部と複数の店舗（あるいは実店舗と EC サイト）が並ぶと、どの拠点の売上がどこに入るかと、誰がどの拠点に属するかを決める必要があります。ユーザー管理は、組織をグループとして表し、メンバーをそこに所属させます。

## グループ

グループは、ウォレットを持つ組織の単位です。本部が上位にあり、店舗A・店舗B のような店舗はその配下に並びます。各グループは自分のウォレットを持ち、店舗の売上はその店舗のウォレットに入ったあと、本部のウォレットに集まります。EC サイトも、実店舗と同じく店舗のグループの1つとして扱えます。

## メンバーの所属

メンバーは、グループに所属し、そのグループの中でロールを1つ持ちます。経営・会計部・店長・スタッフといった役職は人に付くラベルで、何ができるかはロールだけが決めます。

| メンバーの役職 | 所属するグループ | ロール |
| --- | --- | --- |
| 経営 | 本部 | Owner |
| 会計部 | 本部 | Approver |
| 店長 | 店舗 | Viewer |
| スタッフ | 店舗 | Viewer |

## 設計の選択

- **グループ ＝ Safe。** 店舗ごとに Safe を1つ置き、本部の Safe が各店舗の Safe のオーナーの1人になることで、店舗側の暴走を止められます。
- **名前 ＝ ENS サブネーム。** `shop.eth` → `a.shop.eth` → `taro.a.shop.eth` と辿ることで、ENS を「設定置き場」から「組織図」に広げられます。
- **人事の情報は画面側に置く。** 役職や所属の履歴まではオンチェーンにせず、ERP になるのを避けます。
